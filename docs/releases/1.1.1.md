# Hotfix 1.1.1: overview order navigation

Related to #21. Solo self-review.

Both View order and View all set the current screen to orders. In 1.1.0, the warehouse clerk could select any of the three visible baseline vehicles, but the screen allowlist excluded orders. The guard immediately reset the screen to overview, creating the reported flash.

Add orders to the warehouse screen allowlist so that both existing links open the selected order for consultation. The server already supplies this role with order references and material costs. Manager and technician action conditions remain unchanged; financial redaction, invoice restrictions and server command authorization remain enforced. No database migration or user-data changes are required.

Verification: strict TypeScript and 17 domain/localization tests passed. Production HTTP integration passed all ten subtests plus parent, including additional assertions that warehouse order consultation exposes no labor, energy, total cost, interventions or invoices and cannot assign, close or start work. Browser regression reproduces both original bounces for all three warehouse vehicles before applying the fix, then verifies both links preserve order selection and remain on the order screen after a polling refresh for warehouse, technician, manager and administrator sessions.
