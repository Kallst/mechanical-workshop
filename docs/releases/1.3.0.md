# Release 1.3.0: hexagonal organization

Date: 2026-11-23, America/Bogota. Related to #28. Solo self-review.

The workshop is organized into domain rules, application use cases and ports, inbound web/HTTP adapters, outbound PostgreSQL/security adapters and bootstrap composition. Mixed server modules and UI-to-persistence type imports are removed. Next.js keeps its conventional app entry points. Folder READMEs and docs/architecture/hexagonal.md explain responsibilities, dependency direction and an end-to-end operation.

Application factories accept injected ports. Locked transaction units retain state/audit/receipt atomicity, replay protection and ownership. Authentication policy thresholds and lifetimes stay in the application while persistence uses database-relative timestamps. Report records are formatted/localized by HTTP presenters. The database schema, credentials, data, public API URLs and business behavior are retained.

Executed checks: strict TypeScript; 26 unit/application/presentation/boundary tests; eight startup checks; eleven production HTTP subtests plus parent; 377 model checks; production build and one-command startup against existing PostgreSQL. Browser account switching, intervention pause/resume, material requests, partial issues, returns, guarded/guided closure, invoice reload persistence, ES/EN CSV and logout passed without page errors. New in-memory ports verify application behavior without a database, including audit-failure rollback, replay, financial redaction, workspace ownership, lockout/expired-lock handling and idempotent seed. Static/dynamic import checks enforce architecture boundaries.

Feature PR #29 GitHub Actions run 45206052186 passed on a fresh Linux runner with PostgreSQL 18. Release CI repeats the supplied workflow after versioning. See docs/evidence/hexagonal-1.3.0.json. In-memory stores are test helpers only. No independent human review, production workload benchmark or participant usability study is claimed. Docker deployment remains outside these checks.
